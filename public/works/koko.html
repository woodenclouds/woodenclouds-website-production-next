DESIGN REFLECTIONS

What We Learned
Building KOKO

Role-first thinking unlocks clarity

Designing for four distinct roles — Owner, Manager, Supervisor, Store — forced us to strip each interface to exactly what that role needs. No noise, no cognitive overload.

Modular systems scale naturally

Building each of the five modules (Workforce, Harvest, Inventory, Finance, BI) as independent components meant new features could be added without disrupting existing flows.

Field users need radically different UX

Store Managers and Supervisors operate in the field with variable connectivity. We designed offline-first mobile workflows with minimal taps, large touch targets, and visual-first data input.

Real-time data changes decision speed

Replacing daily paper reports with live dashboards reduced the decision-making lag from 24 hours to near-instant. Owners could act on harvest data the moment it was logged.

Approval flows need visual trust signals

Finance approvals across estates required audit trails and visual status indicators at every step. Users needed to trust the system before they'd let go of paper records.

Domain knowledge is the real design tool

Understanding estate operations — crop cycles, weight-based harvesting, estate transfers — was more valuable than any UI pattern library. The best interface decisions came from plantation floor visits.
